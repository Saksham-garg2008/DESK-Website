Good software
is built together.

Contributions can improve code, documentation, tests, platform behavior, and the experience of using DESK. Small, focused changes are welcome.

Read contribution guide ↗Browse issues ↗

A PRACTICAL WORKFLOW

Make changes that are easy to review.

01

Understand first

Read the README and relevant modules before changing behavior. Check existing issues and discussions to avoid duplicate work.

02

Keep it focused

Prefer small, clearly scoped changes. Keep platform-specific behavior isolated and avoid adding dependencies without a clear reason.

03

Test and explain

Test the affected workflow where possible. Describe what changed, why it changed, and what you tested in the pull request.

PROJECT STRUCTURE

Know where your change belongs.

core/

Core services and application logic.

ui/

Desktop interface components.

config/

Application configuration files and defaults.

Companion/

Companion-related code within the main DESK repository.

DESK-Companion

Separate Android Companion repository ↗

A

DESKTOP APP

Keep the app lightweight

Preserve DESK's modular design. Avoid unnecessary heavy frameworks and keep dependencies purposeful, especially where they affect installation and lower-resource machines.

⌘
B

ANDROID COMPANION

Keep the boundary clear

When a change touches Companion code, explain whether desktop-side changes are also required. Document any communication or behavior changes and test the end-to-end workflow when possible.

◇
C

PULL REQUESTS

Give reviewers context

Summarize the change, list affected files or components, explain compatibility implications, and include the tests performed. For UI changes, screenshots can help reviewers when appropriate.

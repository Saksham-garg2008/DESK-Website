DESK / CAPABILITIES

Designed around
useful actions.

DESK connects an AI interface with a modular application layer. The capabilities below describe the current direction of the project, not a promise of unrestricted computer control.

01

ACTION LAYER

Structured requests

Supported actions are represented in a structured format so application code can interpret and validate them. This is intended to be more dependable than blindly turning arbitrary text into shell commands or URLs.

↗
02

DESKTOP INTEGRATION

Applications and browser destinations

DESK includes logic for opening supported desktop applications and web destinations. Actual behavior depends on the operating system, installed applications, and the current implementation.

⌘
03

ARCHITECTURE

Separate responsibilities

Core modules separate concerns such as inference, action execution, memory, history, configuration, and artifact handling. This helps contributors understand and improve individual parts without turning the whole app into one large script.

▤
04

PROJECT ECOSYSTEM

Android Companion

The wider project includes an Android Companion codebase. Some code is in the Companion folder in DESK, with a dedicated project at DESK-Companion.

◇

A NOTE ON SCOPE

Open development means honest boundaries.

DESK is actively developed. Capabilities may vary between releases; consult the repository and release notes for the most accurate implementation details. Features shown here should not be interpreted as guarantees of autonomous or unrestricted system access.
